# איך מקליטים ושומרים קבצי שמע בעברית (Gemini TTS + יישור מילים)

המסמך הזה מסביר לצ'אט אחר, בפרויקט אחר, איך לייצר הקלטות קול בעברית כמו שעשינו במשחק "מפרץ האותיות". זה עובד במכסה החינמית של Gemini. כל קטע נשמר כ-MP3 יחד עם JSON של זמני המילים, כדי שאפשר יהיה להדגיש כל מילה בזמן שהיא נאמרת.
התבנית המלאה נמצאת בריפו `xsprite85-bit/letters-bay`, בתיקייה `src/voice/`: `daily_voice.py`, `mk_manifest.js`, `align.py`.

---

## 1. מה צריך לפני שמתחילים

- **מפתח Gemini API**: מעבירים אותו רק כמשתנה סביבה (`GK=...`). לא לשמור אותו בקובץ, לא לעשות לו commit ולא להדפיס אותו בהודעות.
- **דומיינים שצריכים להיות מותרים** (Settings → Capabilities):
  - `generativelanguage.googleapis.com`: הקול עצמו.
  - `huggingface.co`, `cas-server.xethub.hf.co`, `us.aws.cdn.hf.co`: הורדת מודל הזיהוי העברי.
- **התקנה**:
  ```bash
  pip install --break-system-packages -q faster-whisper huggingface_hub numpy
  # צריך גם ffmpeg ו-node (בשביל ה-manifest)
  ```

## 2. הרעיון בקצרה

1. **Manifest**: רשימה של כל המשפטים והמילים שצריך להקליט. לכל פריט יש `id`, `kind` (`word` / `story` / `comp`), `text` ו-`voice`.
2. **קבוצות (batches)**: לא מקליטים כל פריט בבקשה נפרדת. מצרפים כמה פריטים לטקסט ארוך אחד ושולחים **בקשה אחת לכל קבוצה**. ככה המכסה היומית מספיקה להרבה יותר פריטים.
3. **יישור (alignment)**: מריצים על ההקלטה הארוכה את מודל Whisper העברי (`ivrit-ai/whisper-large-v3-turbo-ct2`) עם זמנים לכל מילה, ומתאימים אותו לטקסט המקורי.
4. **חיתוך**: חותכים מההקלטה הארוכה קובץ MP3 לכל פריט ושומרים לידו JSON עם זמני המילים.
5. **דוח**: כותבים `report.json` עם מה שהוקלט, מה ש"חלש" (זוהה גרוע) ומה שעוד נשאר להקליט.

## 3. הבקשה ל-Gemini

```python
body = {"contents": [{"parts": [{"text": text}]}],
        "generationConfig": {"responseModalities": ["AUDIO"],
          "speechConfig": {"voiceConfig": {"prebuiltVoiceConfig": {"voiceName": "Kore"}}}}}
# POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash-tts:generateContent
# header: x-goog-api-key: <key>
# התשובה: candidates[0].content.parts[0].inlineData.data = PCM base64, 16-bit, mono, 24kHz
```
שומרים את ה-PCM כ-WAV (1 ערוץ, 2 בתים לדגימה, 24000Hz). כדי לחשב את האורך בשניות מחלקים את מספר הבתים ב-48000.

**קולות שבחרנו**: מספר = `Kore`. לדמויות: צב = `Umbriel`, תמנון = `Leda`, דג זוהר = `Puck`. בפרויקט חדש אפשר לבחור קולות אחרים, רק לשמור על קול קבוע לכל דמות.

## 4. כללים חשובים (למדנו אותם בדרך הקשה)

- **שולחים רק טקסט בעברית, בלי הוראות באנגלית.** הוראה כמו "Read slowly..." בתוך הטקסט פשוט נקראת בקול.
- **כל פריט נגמר בסימן פיסוק** (נקודה, ?, !). ככה הקריין עוצר בין פריטים, והחיתוך יוצא נקי.
- **גודל קבוצה**: עד כ-30 מילים בודדות, קטעי סיפור עד כ-650 תווים, ועד 20 משפטים לכל דמות. **כל קבוצה בקול אחד בלבד.**
- **קודם המספר, אחר כך הדמויות**: ככה הדברים החשובים נגמרים ראשונים.
- **ניקוד**: אפשר לשלוח טקסט מנוקד. לפני ההשוואה לזיהוי מנרמלים את שני הצדדים: מורידים ניקוד, משאירים רק אותיות א–ת, ו-`יי`→`י`, `וו`→`ו`.
- **מכסה (429)**: אם התשובה אומרת "retry in" עם המתנה קצרה, מחכים ומנסים שוב. אם ההמתנה ארוכה מ-15 דקות, או שכתוב `per day` עם `limit: 0`, עוצרים בצורה מסודרת וממשיכים מחר. בין בקשות מחכים כ-25 שניות.
- **קליפ "חלש"**: אם פחות מ-60% מהמילים זוהו בדיוק, מסמנים אותו ב-`weak` ומקליטים אותו מחדש בפעם הבאה.

## 5. החיתוך

- תחילת הקליפ: 0.18 שניות לפני המילה הראשונה.
- סוף הקליפ: כ-0.05–0.4 שניות אחרי המילה האחרונה, אבל לא מעבר לתחילת הפריט הבא.
- `ffmpeg -ss A -to B -i batch.wav -ac 1 -ar 24000 -b:a 48k clip.mp3`
- זמני המילים ב-JSON יחסיים לתחילת הקליפ.

## 6. פורמט הקבצים שנשמרים

```
clips/<id>.mp3
clips/<id>.json  →  {"text": "...", "dur": 2.93, "w": [[0.18,0.54], ...], "matched": 1.0,
                     "comp": "g", "voice": "Puck"}   // comp/voice רק לשורות של דמויות
```
- `w` = זוג [התחלה, סוף] לכל מילה בטקסט (המילים מופרדות ברווחים).
- **פריט נחשב "חסר"** אם אין לו JSON, או אם ה-`text` ב-JSON שונה מהטקסט ב-manifest. ככה שינוי בטקסט במשחק גורם להקלטה מחדש באופן אוטומטי.
- את `raw/` (ההקלטות הארוכות) לא מעלים לריפו.

## 7. איך המשחק משתמש בקבצים

`build.py` עובר על `clips/*.json`, מטמיע כל MP3 כ-`data:audio/mpeg;base64` ובונה מילון **לפי הטקסט המדויק**:
`AUD[text] = {src, dur, w}`, ולשורות של דמויות `AUDC[comp][text]`. בזמן ריצה המשחק מחפש את הטקסט. אם יש הקלטה הוא מנגן אותה ומדגיש מילים לפי `w`, ואם אין הוא נופל חזרה לקול של הטלפון.
בפרויקט חדש: אותו רעיון. מפתח המילון הוא הטקסט, ולא צריך לשנות קוד כשמוסיפים הקלטות.

## 8. הרצה יומית

```bash
cd src/voice && GK=<key> python3 daily_voice.py      # אפשר להוסיף --max-requests N
cat report.json   # done / weak / pending_after / stopped
cd .. && python3 build.py                              # להטמיע את הקליפים החדשים
```
אחר כך בודקים שהדף נטען בלי שגיאות (Playwright), עושים commit לקליפים ול-report.json (בלי המפתח ובלי raw), ומעלים.
אפשר להגדיר את זה כמשימה מתוזמנת יומית: כל יום מקליטים מה שהמכסה מאפשרת, עד ש-`pending_after` מגיע ל-0.

## 9. תיקון קליפ בודד

`align.py in.wav "הטקסט" out_id [--from SEC] [--to SEC]` מיישר ושומר קליפ אחד מתוך הקלטה קיימת. זה שימושי כשרוצים לתקן פריט אחד בלי לבזבז בקשה.

## 10. רשימת בדיקה לפרויקט חדש

1. להעתיק את `daily_voice.py` ו-`align.py`.
2. לכתוב `mk_manifest` שמוציא את כל הטקסטים מהקוד של הפרויקט החדש (עם `id` יציב וקול לכל פריט).
3. לבחור קולות ולהוסיף לכל פריט `voice`.
4. לוודא שהדומיינים מותרים ושהמפתח מועבר רק דרך משתנה סביבה.
5. להריץ, לקרוא את report.json, להקשיב ל-2–3 קליפים ולהקליט מחדש את החלשים.
6. במשחק או באתר: לחפש הקלטה לפי הטקסט, ואם אין, לנפול חזרה ל-speechSynthesis.
